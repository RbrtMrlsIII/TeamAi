## 1. What TeamAi has already surpassed

### Product-shape ambiguity
The final 029 experience is no longer treated as the historical single-shell Command Deck. The current target is `Public Entrance → explicit 3D World → coherent spatial machine → Authentication → restored authorized state → configuration/Settings → center workspace → turn/orchestration/evidence`. Historical V0–V3.5 completion remains valuable evidence, but it is not the current C9 product-acceptance authority.

### Public-root ambiguity
The public root is the conventional `public/` entrance. `/hero/` is a compatibility publication of the same source. The historical topology that exposed `frontend/spatial/` as the public root was superseded.

### Command Deck dependency
The historical Command Deck is retired as a current product/deployment surface. `/spatial/` must not be published as the current product route. Historical `frontend/spatial/**` source, contracts, tests, commits, and documents remain preserved for reconstruction and evidence.

Retirement means surface authority was removed, not underlying capability. Seat configuration, Planning/Working context, approvals, artifacts, status/recovery, and Settings are re-owned by the spatial machine, authenticated workspace, world-map Settings, and center workspace model.

Reactivating or renaming the Command Deck requires a new explicit Product Law decision plus full governed reconciliation.

### Legacy implementation inertia
Historical camera paths, prototype coordinates, ambient effects, animation timings, and old Command Deck presentation mechanisms are replaceable implementation baselines. They must not constrain the future adaptive tree/branch/division machine or semantic electrical topology. The correct construction direction is `semantic meaning → payload → expansion requirements → adjacency/connection topology → adaptive geometry → camera/travel → interaction → contribution visualization`.

### Tree-census overclaiming
The Tree Census is a semantic/current-structure baseline, not proof that the complete Hero implementation exists. Current families include `TREE-DOMAIN`, `TREE-HERO-SEAT`, and `TREE-SKILL-RESPONSIBILITY`. Their states remain incomplete/partial where appropriate. A partial Seat mechanism must not be promoted to complete multi-tree machine status merely because it renders successfully.

### C2/C5/C6 foundations
The baseline has advanced through concrete slices: duplicate camera-wall controls were removed from the active DOM; world navigation was consolidated; tree/subject zoom-out reaches the normal `HERO_WIDE` baseline at the configured threshold while the tree is open; classic first-paint duplicate brand/footer chrome was suppressed without destroying world-mode runtime surfaces; and Hero runtime delivery was hardened around repository-owned source rather than remote browser runtime loading. These are foundations, not C8/C9/C10 completion.

### Backend surface drift
The connected Supabase deployment baseline is eight ACTIVE TeamAi Edge Functions. The obsolete `paypal-webhook` deployment is absent from the connected runtime, while `teamai-paypal-webhook-v5c` remains canonical. Historical deployment evidence is retained as historical evidence and is not rewritten to look current.

### Durable task lease preservation
A lease update must preserve the entire Firestore typed field map and overlay only lease-owned fields. Rebuilding durable task state from only string-valued properties risks losing numbers, booleans, maps, arrays, and future fields. General pattern: `partial operation ownership → overlay only owned fields → preserve unrelated durable fields verbatim`.

## 2. Governance lessons proven in practice

### Fail-closed governance is intentional
A governed implementation-root change must reconcile its required active indexes in the same PR. The validator is deliberately fail-closed so repository code, current-state maps, Masterplan, backend status, and skill wiring cannot drift apart.

### Green tests do not outrank governance
A passing unit test, Playwright run, deployment, or staged asset cannot substitute for the applicable governance gate. Governance failure correctly blocks later validation rather than being hidden.

### Validators must express the new truth
The correct response to a changed product requirement is to update the authority/contract and then update its validator through the same governed change. Weakening a validator to obtain green CI is itself a product/governance defect.

### Freshness is part of correctness
An index that contains old truth is not current truth. Required active indexes must be synchronized with the implementation they describe, and freshness is part of merge readiness.

## 3. Validation and browser lessons

### Playwright vs Opera
Playwright is the deterministic browser-proof layer for reproducible assertions and state transitions. Opera is a useful deployed-human observation layer: accessibility-tree inspection, real navigation, screenshots, and direct inspection of the actual published surface. It complements Playwright rather than replacing it.

Useful evidence ladder: `source/static → CI → Playwright → deployed-browser observation → owner/product acceptance`.

### Test the real transition
Browser proof must exercise the actual runtime state machine. C6 proof, for example, must open the seat tree through the real runtime path before asserting the world-baseline camera. Isolated helper invocation can skip the state that makes the behavior meaningful.

### Frontend display is not backend proof
A visible connection, entitlement, task, approval, or status is presentation evidence only. Backend authority, persistence, authorization, scheduler eligibility, and external provider truth require evidence from their authoritative boundaries.

## 4. PR / Issue execution lessons

## 5. Authority boundaries reinforced

The operational chain is `Product Law → Masterplan → Policy/ORUCAVEAM → Skill Wiring → implementation → verification → evidence → HandOver/Endorsement → Product Knowledge`.

Product Knowledge learns from this chain and does not jump ahead of it. The renderer does not grant entitlement, authorization, scheduler authority, durable domain authority, or provider execution authority. Skills provide operational knowledge/procedure, not permission. Workspace rulesets adapt TeamAi concepts to native workspace semantics; they do not replace TeamAi Product Law.

## 6. Knowledge continuity lessons

The useful handoff unit between separate AI applications is an authorized context packet, not the latest model response: `authority + current purpose/state + relevant discussion + durable state + workspace state + restrictions/decisions + evidence + handover → next eligible Seat`.

Therefore `latest AI output ≠ latest authority`. Summarization preserves material decisions, disagreements, constraints, warnings, unresolved questions, and evidence for review; it does not become automatic canonical mutation authority.

## 7. Spatial machine lessons

Every future tree/branch/division change starts from semantic truth and builds outward. Expandable divisions use `CLOSED → PREPARING → OPENING → ACTIVE → CLOSING → CLOSED`.

Connection/electrical effects must correspond to actual semantic graph edges. Decorative disconnected electricity is not acceptable evidence of connectivity. The intended turn-loop is `active turn → active tree/branch → participating divisions open → actual connection path → connected adjacent divisions → center workspace`.

ProMax is downstream of structural correctness and owner acceptance. It cannot be used to conceal missing semantics, topology, camera travel, or verification.
