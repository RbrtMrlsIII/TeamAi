# TeamAi 3D Hero — Vision Reference: Hailuo Mechanical Spatial Machine

**Status:** USER-ENDORSED VISUAL REFERENCE · non-authoritative

**Purpose:** preserve the visual direction endorsed for the TeamAi mechanical 3D Hero without promoting the reference into Product Law, structural truth, or implementation evidence.

## 1. Reference disposition

The Hailuo reference is adopted as a **visual-direction reference** for the spatial-machine experience.

It is not:
- a literal mesh specification;
- a source of semantic tree identity;
- a geometry measurement authority;
- a backend, scheduler, authorization, entitlement, or durable-state authority;
- evidence that the current TeamAi implementation already satisfies the visual direction.

The canonical experience authority remains `docs/VISION.md`, subordinate to `Product_Law/PRODUCT_LAW.md`.

## 2. Endorsed visual cues

The reference establishes the following desired qualities for the TeamAi machine world:

1. **A central working core**
   - The machine reads as an active central system rather than a static ornament.
   - Peripheral structures relate spatially to the center.

2. **Independent articulated modules**
   - Surrounding units feel mechanically separate and capable of opening, extending, rotating, retracting, or otherwise reconfiguring.
   - A Seat/tree/division should be able to behave as an articulated assembly rather than as a flat card.

3. **Connected machine topology**
   - Connections are visible as spatial paths between meaningful parts.
   - Wires/threads should visually reinforce real semantic relationships, never replace them.

4. **Transformation as interaction language**
   - User actions should be capable of changing the machine's spatial state.
   - Opening a parent can reveal child mechanisms; focusing a division can cause related geometry and camera framing to respond.
   - The machine should feel like one system changing configuration, not a static model with unrelated animations.

5. **Camera participation**
   - Camera movement is part of the transformation.
   - The user should be able to travel into, around, and back out of the machine while semantic subject identity remains stable.

6. **Layered mechanical depth**
   - Nested rings, shells, mechanisms, corridors, and internal parts can communicate depth and hierarchy.
   - Visual density may vary with semantic/UI payload rather than being forced into one universal prototype shape.

## 3. TeamAi translation

The intended conceptual mapping is:

```text
semantic tree / graph
        ↓
spatial machine structure
        ↓
articulated module state
        ↓
semantic connection paths
        ↓
camera + transformation choreography
        ↓
workspace relationship
```

The machine is therefore not merely:

```text
3D tree + animation
```

and not merely:

```text
3D model of a machine
```

The intended experience is:

```text
A semantic spatial machine that transforms itself according to what the user is doing.
```

## 4. Explicit implementation boundary

The current TeamAi implementation remains partial.

Existing implementation slices provide pieces of this direction, including semantic machine structure, payload-driven geometry, connection topology, adaptive clearance, and stateful expansion/interruption behavior. Those pieces must continue to be verified against their governing contracts and current runtime evidence.

The reference does **not** authorize:
- replacing canonical semantic identities with visual shapes;
- inventing backend state from animation;
- declaring production Hero replacement;
- declaring C8/C9/C10 completion;
- weakening validation because a visual outcome resembles the reference.

## 5. Fidelity rule

Use the reference to answer **“what should the machine feel and look like?”**

Use the canonical TeamAi contracts, tree census, implementation lineage, runtime evidence, and Product Law to answer:
- what the machine means;
- which object owns a behavior;
- what a connection actually represents;
- how geometry is computed;
- what may open or transform;
- what evidence is required.

When those sources conflict, the visual reference yields to the canonical project authority.
