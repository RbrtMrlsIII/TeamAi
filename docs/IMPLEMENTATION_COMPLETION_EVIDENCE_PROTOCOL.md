# Implementation Completion Evidence Protocol

Status: CANONICAL EXECUTION DISCIPLINE

## Rule

Implementation status is evidence-backed, not document-backed.

A capability can be marked `IMPLEMENTED` only when executable repository evidence,
validation evidence, contract authority, and completion closure are all linked in the
Foundation Implementation Completion Matrix.

The following are never sufficient by themselves:

- Product Law;
- Masterplan;
- handover/session notes;
- endorsement records;
- high-fidelity concepts;
- spatial/3D concepts;
- screenshots;
- continuity/checkpoint records;
- a planning contract;
- a present-day human authorization.

## Promotion rule

Status promotion is append-only in evidence: the status may change only after a new
evidence record is created or identified, with concrete repository/test references.
A later agent may not delete or weaken an open completion frontier merely to make a
phase appear complete.

## 029 hard gate

Before production frontend implementation may be reported as complete, all
`BLOCKS_029` rows must be closed or explicitly re-scoped with an approved execution
boundary. `CAN_DEFER` rows may remain open only when no implementation claim depends
on them.
