## Tree-machine construction rule

For any tree/branch/division work, design from semantic truth outward:

`root truth → treeID / branchId → purpose / responsibility → UI/product payload → expansion requirements → connection topology → adaptive geometry → camera/travel → interaction → contribution routing → verification`

A branch is a real product integration, not a decorative mesh. Trees may be broad, asymmetric, recursive, and differently sized. Geometry is payload-driven. Expansion must reserve payload, neighboring-division clearance, wiring corridors, camera movement, workspace visibility, and responsive readability.

Whenever a tree, branch, division, associated connection behavior, expansion behavior, or semantic UI payload is added, removed, renamed, materially restructured, or reimplemented, the same governed change must reconcile the synchronized tree census:
