## Governance lessons proven in practice

- Fail-closed governance is intentional. Implementation-root changes must reconcile the applicable active indexes in the same governed PR.
- Green unit tests, Playwright, deployment success, or documentation presence cannot substitute for the applicable governance gate.
- When requirements change, update the canonical contract/authority and its validator through the authorized path. Never weaken a validator to manufacture a green result.
- Freshness is part of correctness: an active index containing stale implementation truth must be reconciled.
- A PR based on stale `main` can be technically correct yet still be invalid as a current-state change. Rebase/recreate against the current baseline before merge.

## Evidence lessons

- Playwright is the deterministic browser-proof layer. Opera is a useful deployed-human observation layer for accessibility structure, navigation, screenshots, and actual published-surface inspection. Opera complements Playwright and does not replace it.
- Browser proof must exercise the meaningful trigger/state path rather than merely invoke an isolated helper.
- A screenshot or visible UI status is not proof of backend persistence, authorization, scheduler eligibility, payment, or provider execution.
- Evidence must be scoped to the exact claim exercised.

## Frontend machine lessons

- The target chronological experience is `Entrance → explicit 3D World → guest default rotating world → authentication transition → restored authorized state → 3D configuration/Settings → readiness → user-started turn → scheduler-backed contribution → evidence/workspace`.
- Login and Sign up belong to the guest authentication transition, not the authenticated Settings taxonomy.
- Selecting Login/Sign up stops guest orbit, expands the full currently-defined tree/branch/division presentation, centers the workspace, reaches the intended authentication framing, and shows the small authentication UI beside the workspace.
- The authenticated Settings menu is a categorical map, not a second semantic tree: Seats; Tree 1–8; Branches; Privacy Policy; Terms; Logout; Return BTN.
- The Entrance owns About, Complex Dictionary/User Guide, public legal content, Contact, Credits, and Footer.
- Every semantic tree uses stable `treeID`; every branch/division uses stable semantic `branchId`. Coordinates, mesh indices, ring slots, and camera docks never define identity.
- A branch is a real integration with purpose, payload, expansion footprint, adjacency clearance, connection ownership, camera relationship, accessibility/responsive rules, and evidence state.
- Branches may be broad, asymmetric, recursive, and differently sized. There is no universal branch height, width, radius, depth, or fixed coordinate template.
- Expandable divisions use a stateful lifecycle such as `CLOSED → PREPARING → OPENING → ACTIVE → CLOSING → CLOSED`. Instant visibility toggles and teleports are not the final machine language.
- During the final contribution loop, participating divisions are active/open so their actual connection corridors exist. Electrical visualization must follow real semantic graph edges toward the workspace center.
- ProMax is downstream of structural correctness, connection topology, camera travel, and C9 acceptance. It must not conceal missing machine semantics.
