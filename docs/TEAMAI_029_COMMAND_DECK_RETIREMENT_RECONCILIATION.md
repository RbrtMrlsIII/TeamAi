# Command Deck Retirement Reconciliation

**Current truth:** The historical Command Deck is retired as a current product/deployment surface.

**Current published surfaces:**

`/` → public Entrance

`/hero/` → Hero compatibility route

`/spatial/` → retired; not published by the current GitHub Pages workflow

## Why the retirement is not a loss of capability

The previous Command Deck bundled many responsibilities into a separate shell. Those responsibilities remain product requirements but are now re-owned by the authenticated spatial machine, semantic tree/division surfaces, and center workspace model defined by Product Law and Issue #278.

The retirement therefore removes a competing surface authority, not the underlying capabilities.

## Historical preservation

Existing `frontend/spatial/**` source, Command Deck contracts, snapshots, tests, and historical PRs remain available for archaeology and reconstruction. They are historical evidence and must not be used as current visual or product authority without a new authorized decision.

## Animation and topology boundary

Retirement also prevents historical Command Deck layout/motion assumptions from becoming constraints on the future tree-machine system. The current prototype motion language remains replaceable. Future division expansion, camera travel, and electrical turn-loop choreography must be designed from semantic tree/branch/division truth and actual connection topology.
