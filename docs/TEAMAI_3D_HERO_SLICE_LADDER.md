## Light-skeomorphic execution ladder

### Slice A — Theme semantic adapter
Issue #84. Translate canonical `frontend/spatial/theme-root.css` semantics into deterministic spatial parameters. Inputs include theme mode, atmosphere, surfaces, focus, signal, status, and motion. Outputs include environmental fill, key-light family, grazing/rim, contribution-light base, roughness/reflectance, shadow separation, emissive bounds, and reduced-motion state. Never create a second theme root.

### Slice B — Manufactured environment + workspace light
Issue #85. Build the physical light relationship: environment fill, workspace key, machined Seat/workspace response, grazing highlights, and restrained depth/contact separation. Light reveals geometry rather than decorating a flat UI.

### Slice C — Contribution + absorption light
Issue #86. Bind light choreography to `FOCUS → ACTIVE → CONTRIBUTE → ABSORB → REFLECT → HANDOFF`. `CONTRIBUTE` follows the authored Seat → workspace corridor; `ABSORB` makes the workspace receive and settle the light; `REFLECT` acknowledges state briefly; `HANDOFF` shifts emphasis to the next eligible Seat. Reduced motion uses static semantic state.

### Slice D — Material + spatial-depth refinement
Issue #88. Refine authored meshes toward manufactured objects: roughness families, reflectance, bevel/grazing response, shell/inset separation, contact shadow, and readable hierarchy across semantic cameras.

### Slice E — Responsive + reduced-motion contract
Issue #89. Ensure the same spatial hierarchy survives narrow viewports and 1–8 Seat densities while preserving semantic camera continuity and the shared-workspace/Seat distinction.

### Slice F — Seat Identity Inspection
Issue #81. After release, extend the semantic inspection ladder into Seat identity, responsibility, current state, connection status, and deeper mechanisms. Stop at normal UI when tasks become text-heavy, configuration-heavy, or precision-sensitive.

## Development rule

One slice should establish one new spatial capability and one verification boundary. Preserve the baseline and previous slices. Prefer additive adapters and authored form refinement over wholesale renderer rewrites. A green render or test does not constitute approval; implementation completion requires the full governing chain and endorsement.
