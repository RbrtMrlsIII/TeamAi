# WORKSPACE_SKILL — ws.authority.map

**Kind:** `WORKSPACE_SKILLS` · `ws.authority.map`  
**Status:** OPERATING PROCEDURE / NOT PRODUCT LAW

## WHEN TO USE

Use when orienting a Seat, contributor, or session to **who owns what** on this project: Product Law, Masterplan, skills, tools, UI, and durable state.

## INPUT

- Current task class (docs, Hero presentation, backend, commerce, verification)
- Any claim that a surface “is” authority (Hero open, green CI, latest AI message)

## AUTHORITY

This skill restates the **authority chain**. It does not amend Product Law.

```text
Human user
  → PRODUCT_LAW.md
  → MASTERPLAN.md (chronological gates)
  → Fields / Responsibility Profiles
  → Workspace rules + Skills (procedure only)
  → Capabilities / tools
  → Authorization
  → Durable task/event state + Scheduler eligibility
```

## ACTION

1. Prefer Product Law + Masterplan over chat recency or branch names.
2. Treat Hero / spatial UI as **presentation** (Family J) — open seat ≠ entitled, ≠ authorized tool.
3. Treat skills and Zip packages as **optional procedures**, not commerce or permission.
4. Treat GitHub as engineering/source authority; TeamAi owns participation and tool policy.
5. Treat Firestore as durable domain store; browser must not self-attest entitlement or completion.
6. When unsure, **STOP** and escalate rather than invent a second constitution.

## DO NOT

- Do not let the 3D Hero, plate toggles, or “Start turn loop” imply live orchestration authority.
- Do not confuse CAPABILITY ≠ AUTHORIZATION ≠ WORKSPACE ≠ FIRESTORE (as the Hero legend states).
- Do not claim 029-released from presentation progress.

## PASS

Session actions stay inside the chain; presentation is not mistaken for permission.
