# Learning + Handover Skill

## WHEN TO USE
Use when an AI Development Team agent discovers a reusable lesson, improved procedure, warning, correction, or more efficient method during execution.

## INPUT
Observed lesson, execution evidence, affected Masterplan item, applicable ORUCAVEAM letter(s), affected field/domain Skill or document, scope, limitations, and whether the lesson is TeamAi-specific or generalizable.

## AUTHORITY
`POLICY.md` defines execution discipline. `Product_Law/PRODUCT_LAW.md` is product authority. `AI_ASSISTANT_READ_ME.md` owns current continuation/recovery/handover/endorsement-decision state. Acceptance is recorded against the exact owning Issue/PR/evidence scope. `PRODUCT-KNOWLEDGE.md` receives only validated reusable learning.

## ACTION
1. Record what was discovered and why it matters.
2. Tie the lesson to the executed Masterplan checklist, applicable ORUCAVEAM letter Skill(s), field/domain Skill(s), and evidence.
3. Identify whether the lesson changes Product Law, procedure, verification, or only session technique.
4. Put current continuation/recovery state in `AI_ASSISTANT_READ_ME.md`.
5. Record acceptance only in the exact owning Issue/PR/evidence record when that boundary is authorized and evidenced.
6. Update the operational Skill when the procedure itself changed.
7. Update `AI_ASSISTANT_READ_ME.md` when the lesson is a practical session/recovery technique.
8. Update `PRODUCT-KNOWLEDGE.md` only when the lesson is validated and worth permanent retention.
9. Propose a ToolKit upstream candidate only after enough evidence and scope analysis exists to test generalization.
10. Preserve historical handover records under `handover/` or `docs/archive/` when they are no longer active.

## DO NOT
- Promote agent opinion directly to Product Law.
- Call a lesson generalized because it worked once.
- Store raw conversation or screenshot evidence in Product Knowledge.
- Change a Skill without checking the governing Product Law, Masterplan, and Policy.
- Hide a changed reusable procedure in a canonical document.
- Create a second live handover manual.
- Create or revive `HandOver.md`.
- Treat a green workflow as acceptance.

## PASS
The lesson has an evidence path, clear scope, identified Masterplan item, applicable Skill destination, and a current-session/acceptance path where required.

## EVIDENCE
Execution result, Masterplan item, source/Skill path, ORUCAVEAM letter(s), verification result, `AI_ASSISTANT_READ_ME.md` state when applicable, exact owning Issue/PR/evidence acceptance when applicable, and Product Knowledge row if promoted.
